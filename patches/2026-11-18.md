## 요청 (하드웨어 작업자)

> 안드로이드 폰 1대에서 입출력을 모두 처리. 남성용·여성용을 **둘 다 연결**해 서로 데이터를 잇는다.
> - 현재 BLE 는 `txChar`(쓰기)만 사용 중 (브라우저→기기)
> - `rxChar`(notify) 추가 (기기→브라우저). 기기·서비스 UUID 는 동일
> - `txChar`/`rxChar` 각 1개씩, **2개 기기 동시 연결** (bleOutput / bleInput 분리)
> - `rxChar` 로 들어온 신호를 `txChar` 쪽으로 **그대로 복사**해 출력

## 설계 — 기존 경로를 건드리지 않는다

`PulseDevice` 는 10여 개 페이지(플레이어·통화·콘솔·방송·함께보기·헤더)가 쓴다.
그래서 **기존 단일 연결(`state`)을 그대로 '출력'으로 두고**, 입력은 완전히 분리된
두 번째 연결(`inState`)로 넣었다. 기존 API 는 **하나도 바뀌지 않았다.**

새 API: `connectBluetoothInput()` · `disconnectInput()` · `setRelay(on)` ·
`getInputStatus()` · `onInput(cb)` · `inputConnected`. `getStatus().input` 에 요약도 들어간다.

## 구현에서 반드시 필요했던 것 (요청서에 없던 부분)

1. **줄 조립** — BLE notify 는 MTU(보통 20바이트)로 쪼개 온다. 한 줄이 여러 알림에 걸쳐 오거나
   한 알림에 여러 줄이 온다. 버퍼에 모아 **개행 기준으로 잘라야** 한다. 버퍼 상한 512B.
   (줄바꿈이 끝내 안 오면 아무것도 내보내지 않는다 — 깨진 조각을 기기로 보내는 것보다 낫다)
2. **릴레이 간격 20ms · 최신값만** — 입력이 초당 수백 줄을 쏟으면 BLE 쓰기 큐가 무한정 밀린다.
   위치 프로토콜이라 **지나간 값은 의미가 없다** → 간격 안에서는 마지막 줄만 보낸다
   (`axis_sender` 가 UI 입력에 쓰는 것과 같은 원칙). 생략한 수를 UI 에 보여준다.
3. **같은 기기 거부** — 출력과 동일한 기기를 입력으로 붙이면 보낸 값이 되돌아와 무한 반복된다.
   물리 액추에이터라 실제로 위험하므로 `device.id` 로 막는다.

## rxChar UUID — 자동 탐색

작업자가 "서비스 UUID 는 동일" 이라고만 알려주고 **rxChar UUID 는 아직 안 줬다**.
그래서 `device_drivers.js` 에 `rxChar: null` 로 두고, 연결 시:

- `rxChar` 가 있으면 그것을 쓴다
- 없으면 서비스의 캐릭터리스틱을 훑어 **notify/indicate 가능한 것**을 고른다
- 연결할 때마다 **전체 캐릭터리스틱 목록(UUID + 속성)을 콘솔에 출력**한다

```
[PulseDevice] 서비스 캐릭터리스틱 목록:
  216f3732-… [write,writeWithoutResponse]
  xxxxxxxx-… [notify]
[PulseDevice] 입력 캐릭터리스틱 자동 선택: xxxxxxxx-…
```

**UUID 가 확정되면 `device_drivers.js` 의 `rxChar` 에 적는 쪽이 빠르고 확실하다.**
(NUS 라면 `6e400003-b5a3-f393-e0a9-e50e24dcca9e`)
