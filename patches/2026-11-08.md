## 왜 코드를 안 건드렸나

런타임 코드에 도메인이 **하드코딩된 곳이 없다**. 확인한 것:

| 항목 | 상태 |
|---|---|
| 링크·리다이렉트 | 전부 상대경로 |
| 세션 쿠키 | `domain` 속성 없음 → 어떤 호스트에서도 동작 |
| `robots.txt` / `sitemap.xml` | 상대경로 |
| `publicUrl()` (`storage.js`) | `/content/...` 상대경로 |
| 도메인이 적힌 곳 | **문서뿐** (`DEPLOY.md`, `HANDOFF.md`) |

→ DNS·터널 설정만으로 교체됐다.

## 전환 절차 (실제로 한 것)

## ⚠ 함정 — `cloudflared tunnel route dns` 는 cert.pem 의 존에만 쓴다

```bash
cloudflared tunnel route dns syncra realhage.com
# → INF Added CNAME realhage.com.syncra.uk   ← 엉뚱한 하위도메인!
```

`~/.cloudflared/cert.pem` 은 `cloudflared tunnel login` 때 **고른 존(syncra.uk) 전용**으로 발급된다.
그래서 다른 존의 호스트명을 주면 **"syncra.uk 의 하위도메인"으로 해석**해 `realhage.com.syncra.uk` 를 만든다.
재로그인하면 cert.pem 이 덮어써져 기존 존 쪽이 불편해지므로, **새 존에는 대시보드에서 직접** 넣는다:

| 존 | 이름 | 형식 | 대상 | 프록시 |
|---|---|---|---|---|
| realhage.com | `@` | CNAME | `54a9f992-1739-414b-9fe6-b437688ecf42.cfargotunnel.com` | **켬(필수)** |
| realhage.com | `www` | CNAME | 같음 | **켬(필수)** |

- 프록시를 끄면 `cfargotunnel.com` 은 외부에서 해석되지 않아 사이트가 안 열린다.
- 저장하면 목록에는 형식이 **"터널"** 로 표시된다. 단 **레코드 추가 창의 형식 목록에는 "터널"이 없다** — CNAME 으로 넣어야 한다.
- 온보딩 스캔이 가져온 후이즈 파킹 A 레코드(`@`, `www` → `118.67.131.217`)는 **삭제**해야 한다.
- 잘못 생긴 `realhage.com.syncra.uk` · `www.realhage.com.syncra.uk` 2개도 syncra.uk 존에서 삭제.

실패했는데 전파 문제였고 곧 정상화됐다 — **새 존에서 바로 안 되면 잠시 기다릴 것.**

## 2차 — 폰 자동 기동 (Termux:Boot)

재부팅·강제종료되면 **sshd·PULSE 서버·터널이 전부** 안 올라와 매번 손으로 Termux 를 열어야 했다
(2026-10-11, 11-08 두 번 겪음). 부팅 스크립트를 넣었다.

**위치:** 폰 `~/.termux/boot/start-pulse.sh` (저장소 사본 `scripts/phone/start-pulse.sh`)

```
① sshd            pgrep -x sshd 로 확인 후 없으면 시작
② PULSE 서버       PORT=5501 · BEHIND_PROXY 안 씀 (현재 운영 환경 그대로)
③ cloudflared     tunnel run syncra  (realhage.com · syncra.uk 둘 다 받는 ingress)
```

### 설계에서 신경 쓴 것

- **멱등**: 이미 떠 있으면 다시 안 띄운다. 수동으로 몇 번을 실행해도 중복 프로세스가 안 생긴다.
- **서버 생존 확인은 `pgrep` 이 아니라 `/health` 응답으로** 한다.
  `pgrep -f "server/app.js"` 는 **자기 자신(ssh 명령줄)까지 잡는다** (RULES R-2).
- 터널 확인도 같은 이유로 **앵커 패턴** `pgrep -f "^cloudflared tunnel run syncra"` 를 쓴다.
  실측: 넓은 패턴은 **3개**(ssh 셸 포함), 앵커 패턴은 **1개**(실제 터널).
- 부팅 직후 10초 대기 — 네트워크·스토리지가 자리잡을 시간.
- 로그는 `~/pulse/data/logs/boot.log` 에 append.
- ⚠ `BEHIND_PROXY=1` 을 넣지 않았다. 켜면 세션 쿠키가 `secure` 가 되어 **LAN HTTP 로그인이 깨진다**
  (기기 테스트 경로). `restart_pulse.sh` 와 다른 점 — 의도적이다.

### 검증

서비스 3개가 **모두 떠 있는 상태**에서 스크립트를 두 번 실행:
- `sshd 1 · node 1 · cloudflared 1` → 실행 후에도 **동일** (중복 0)
- `boot.log` 에 "이미 실행 중" 3줄 + `{"ok":true}`

### 사용자가 해야 하는 것 (앱 설치는 대행 불가)

1. **Termux:Boot 설치** — **Termux 를 받은 곳과 같은 출처**에서 받아야 한다(F-Droid ↔ GitHub).
   서명이 다르면 Android 가 Termux 데이터 접근을 거부한다. Play 스토어판은 폐기됨.
2. **설치 후 앱을 한 번 실행** — 그래야 부팅 이벤트를 받는다. 빈 화면이 정상.
3. **배터리 최적화에서 Termux 제외** (+ 일부 ROM 은 "자동 실행 허용" 별도 설정).
4. 재부팅 1회로 확인. 부팅 후 `~/pulse/data/logs/boot.log` 와 `https://realhage.com/health` 확인.
