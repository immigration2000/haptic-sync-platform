## 영상 다운로드 입구 차단

플레이어에 브라우저 기본 **⬇ 다운로드 버튼**이 그대로 노출돼 있었다.

| 닫은 것 | 방법 |
|---|---|
| 네이티브 컨트롤의 다운로드 버튼 | `controlsList="nodownload"` |
| 원격 재생(캐스팅) | `noremoteplayback` + `disableRemotePlayback` |
| 영상 우클릭 "비디오를 다른 이름으로 저장" | `contextmenu` 차단 (VIDEO) |
| VR 캔버스 우클릭 "이미지를 저장" (프레임 갈취) | `contextmenu` 차단 (CANVAS) |

### 왜 뷰마다 박지 않고 한 곳에 뒀나

영상 요소가 **7개 뷰**에 흩어져 있고, 통화·함께보기·VR 폴백은 영상을 **나중에 만들거나
`controls` 를 뒤늦게 붙인다**(`player.js vrFallback`). 뷰마다 속성을 박으면 반드시 빠진 데가 생긴다.
→ `public/js/core/no_download.js` 를 `layout.ejs` 에서 한 번 로드하고,
   나중에 생기는 영상·늦게 붙는 `controls` 까지 `MutationObserver` 로 따라간다.
   우클릭 차단도 document 캡처 단계에서 한 번만 잡는다.

## 2차 — 미디어 파일 인증 게이트 (**서버 재시작 1회**)

`main cf5bb4d` · 재기동 PID 24732 → **32216**

### 무엇이 구멍이었나

콘텐츠가 `public/content/` 에 있어 `express.static` 이 **인증 검사보다 먼저** 서빙했다.
플레이어 라우트(`/content/play/:id`)는 `requireAgeVerified` 인데 **파일은 무인증**이었다.
→ 사이트 출입 게이트만 지나면 로그인·연령확인 없이 주소창으로 영상을 직접 받을 수 있었다.

### 어떻게 막았나

`server/middleware/media_gate.js` 를 **`express.static` 보다 먼저** 마운트.

| 대상 | 판정 |
|---|---|
| `/content/**/*.{mp4,webm,mov,m4v,mkv,avi,ts,m3u8,funscript,csv}` | 로그인 + 연령확인(admin 통과) 아니면 **403** |
| `/content/**/*.{jpg,png,…}` (썸네일·포스터) | 통과 — 비로그인 카탈로그가 깨지면 안 된다 |
| `/content/vod`, `/content/play/3` 등 **라우트** | 통과 — 각 라우트 미들웨어가 검사 |
| `/content` 밖 | 간섭 없음 |

- **디렉터리가 아니라 확장자로 가른다.** BJ 업로드는 `content/bj/<id>/` 에 영상·funscript·
  `_thumb.jpg` 가 섞여 있고, 새 업로드 경로가 생겨도 확장자 기준이면 자동 보호된다.
  funscript 도 보호 대상 — 동작 데이터 자체가 콘텐츠다.
- **우회 차단:** 퍼센트 인코딩(`%76ods`), `..` 로 디렉터리 건너뛰기, 백슬래시, 대문자 확장자를
  모두 정규화해서 판정한다. `serve-static` 이 경로를 디코드·정규화해 파일을 찾기 때문에
  게이트도 같은 눈으로 봐야 한다 (단순 `startsWith` 는 우회된다).
- **파일 전송은 손대지 않았다.** 통과하면 기존 `express.static` 이 서빙 → Range(탐색)·ETag·304 불변.
- `views/home.ejs` 히어로: 비로그인에게는 **포스터만**. 게이트가 403 으로 끊으므로 `src` 를 비운다
  (크롤러에 2.7GB 를 흘릴 이유도 없다).

### 재시작 — `restart_pulse.sh` 를 쓰지 않았다

그 스크립트는 `BEHIND_PROXY=1` 을 넣는데 현재 프로세스에는 그 값이 없었다. 켜지면
세션 쿠키가 `secure` 가 되어 **LAN HTTP(192.168.x:5501) 로그인이 깨진다**(기기 테스트 경로).
이번 변경과 무관한 동작 변화이므로 환경을 그대로 재현해 띄웠다:

```bash
cd ~/pulse && termux-wake-lock
kill <PID>; sleep 3
setsid env PORT=5501 node server/app.js > data/logs/run_$(date +%Y%m%d_%H%M%S).log 2>&1 < /dev/null &
```

`BEHIND_PROXY` 를 켤지는 **별건으로 판단할 일**이다 (켜면 공개 사이트 쿠키 보안은 올라가고
LAN HTTP 로그인은 못 쓴다).
