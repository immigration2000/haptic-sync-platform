기존 버튼은 **쿠키만** 지웠다. 캐시를 안 건드려서 그 증상을 못 고친다.

## 바꾼 것

| | 전 | 후 |
|---|---|---|
| `Clear-Site-Data` | `"cookies"` | **`"cookies", "storage", "cache"`** |
| 기본 동작 | 쿠키만 | **전부 정리** (체크박스는 `장치·재생 설정은 남기기` 로 **opt-out** 반전) |
| 정리 후 | 완료 페이지에 머무름 | **`/?fresh=<ts>` 로 `location.replace`** — 캐시된 HTML 이 아닌 새 응답 |
| 응답 헤더 | — | `Cache-Control: no-store` (이 페이지가 캐시에 남으면 안 된다) |

- **`"cache"` 가 `Ctrl+Shift+R` 역할**이다. 단축키는 그 한 번만 우회하지만 이쪽은 **비운다** — 더 확실.
- **체크박스를 반전한 이유:** 카메라 증상은 `localStorage` 의 **잘못 저장된 카메라 선택**
  (`pulse_cam_device` — 예: 사라진 장치, OBS 가상캠)이 원인인 경우가 많다. 그걸 지워야 고쳐지므로
  기본은 지우고, 굳이 남기고 싶을 때만 체크하게 했다. 안내 문구에도 "카메라 문제면 켜지 마세요" 라고 적었다.
- **폴백**: Cache API·서비스워커를 JS 로 직접 삭제. `Clear-Site-Data` 는 **HTTPS 전용**이라
  사파리·LAN http 에서는 안 먹는다.
- 카메라·마이크 **권한**은 브라우저 소관이라 우리가 못 지운다 — 안내에 명시(주소창 자물쇠).

## ⚠ 재기동 로그에서 발견한 **기존 문제** (이번 변경과 무관)

```
ValidationError: The 'X-Forwarded-For' header is set but the Express 'trust proxy'
setting is false … ERR_ERL_UNEXPECTED_X_FORWARDED_FOR
```

Cloudflare 터널이 `X-Forwarded-For` 를 붙이는데 `trust proxy` 가 꺼져 있다.
→ **rate limit 이 방문자별로 안 걸리고 전원이 한 양동이를 공유**한다.
오리진이 보는 소켓 IP 가 항상 `127.0.0.1`(cloudflared) 이기 때문이다.

- 일반 200회/분, **인증 10회/분** 이 전체 합산 → 사람이 몰리면 **정상 사용자가 429 로 막힐 수 있다**
- 고치려면 `app.set('trust proxy', 1)` + `BEHIND_PROXY=1` 인데, 그러면 **세션 쿠키가 `secure`** 가 되어
  **LAN HTTP 로그인이 깨진다**(기기 테스트 경로). 그래서 지금까지 일부러 안 켰다 — `patches/2026-10-10.md`
- **운영 공개 전에는 켜는 쪽이 맞다.** 그때 LAN 테스트는 `localhost` 터널이나 https 로 옮겨야 한다.
