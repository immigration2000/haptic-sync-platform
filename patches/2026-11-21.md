## 1. 작업자 실기기 영상 분석 (2026-11-21 수신, 30.8초)

### 결론: **출력 기기가 30.8초 내내 한 번도 움직이지 않았다.**

"끊겨서 움직인다"가 아니라 **아예 안 나갔다.** 어제 고친 릴레이 타이밍 문제
(위치 역전·큐 누적)와는 다른 층위의 문제다.

### 어떻게 확인했나

카메라가 손에 들려 있어 흔들림이 섞인다 → **컨트롤러의 파란 LED 를 기준점**으로 잡아
매 프레임 같은 위치로 정렬한 뒤 기기 영역만 잘라 **0.5초 간격 62장**을 비교했다.
**62장 전부 링키지 자세가 동일하다** — 검은 암의 각도, 황동 조인트, 오른쪽 갠트리 전부.

보조 증거:
- **오디오에 서보음이 없다.** 60–300Hz 생활소음만 연속으로 깔리고 중·고역은 손으로
  만질 때 몇 번 튀는 게 전부. 액추에이터가 돌면 나와야 할 연속 기계음이 없다.
- **컨트롤러 전원은 들어와 있다** — 파란 LED 가 30초 내내 켜져 있다.

⚠ **실패한 접근도 남긴다** — 픽셀 차분으로 움직임 양을 재려 했으나,
**대조군(움직일 리 없는 본체 흰 상자)이 링키지보다 수치가 더 높게** 나왔다.
LED 주변은 밝아 정렬 잔차가 크게 증폭된다. 흔들리는 영상에서 차분 에너지는 신뢰할 수 없다.
→ **대조군 없이 차분 수치를 믿지 말 것.** 정렬 후 눈으로 비교하는 쪽이 정확했다.

### 못 읽은 것

**노트북 화면 글씨는 끝내 못 읽었다.** 240프레임을 위상상관으로 정합·누적까지 했지만
카메라 해상도 한계다(1080px 중 화면이 400px). 구조만 보인다 — 다크 UI, 좌상단 버튼 4개,
큰 검은 패널, 그 안 우측에 초록 글자 열 + 회색 글자 열, 아래 작은 안내문 한 줄.
우리 진단 창처럼 보이지만 **확정 못 한다.** 따라서 수신 카운트·연결 상태·생략 사유를
알 수 없고, 아래 후보를 영상만으로는 가릴 수 없다.

| 후보 | 진단 창에서 보이는 모습 |
|---|---|
| 출력 기기 미연결 | 송신요청 0 · 생략 사유 **"출력 미연결"** |
| 입력은 붙었는데 수신 0 | **수신 0** — notify 미발신 또는 **줄 끝 개행 없음** |
| 복사 토글 꺼짐 | 생략 사유 **"복사 꺼짐"** |
| 복사는 나가는데 기기가 무시 | 송신요청·**쓰기완료는 오르는데** 무동작 → 명령 포맷/드라이버 |
| 값이 안전 범위 밖 | 위와 같되 특정 축만 |

→ 작업자에게 **진단 창 로그 파일**을 요청했다. 영상으로는 여기까지가 한계다.
  화면을 찍을 거면 **노트북 화면만 가까이서** 찍어야 읽힌다.

## 2. 진단 창 — 축 위치 막대 (수신 vs 송신)

숫자만으로는 "어디로 어떻게" 움직이는지 안 보인다는 요청. 축마다 **수신·송신 두 줄**의
슬라이더 막대와 최근 5초 궤적을 그린다.

| 요소 | 뜻 |
|---|---|
| 막대 | 보간(`I`)을 반영한 **지금 있어야 할 위치** |
| 흰 눈금 | 마지막으로 받고/보낸 **목표값** |
| 곡선 | 최근 5초. **수신을 굵게 아래, 송신을 가늘게 위에** 그린다 |
| 지연 | 수신 줄과 **같은 문자열**이 복사로 나갈 때까지의 시간 (평균·최대) |

곡선을 굵기 다르게 겹쳐 그리는 이유: 그대로 전달되면 초록이 파란 띠 **안에** 들어앉아
"겹쳤다"가 한눈에 보이고, 어긋나면 파란 띠가 밖으로 비져나온다.

**로그 이벤트만 보고 그린다 — `device.js` 는 건드리지 않았다.** 그래서 다른 탭의
입출력도 그대로 들어오고, 기존 동작에 영향이 없다.

막대는 로그 **'멈춤' 중에도 계속 돈다.** 멈춤은 목록을 멈추는 것이고 막대는 현재 상태를
보여야 하기 때문이다.

### 🔴 requestAnimationFrame 을 쓰면 안 된다

처음엔 rAF 로 짰는데 **한 번도 호출되지 않았다.** 창이 가려지거나 합성되지 않는 상황에서
rAF 는 아예 멈춘다 — 그러면 막대가 멈춘 채 **옛 값을 띄워 거짓 상태를 보여준다.**
상태 표시에서 이건 치명적이다. `setInterval(33ms)` 은 숨은 탭에서 느려질 뿐 멈추지 않는다.

### 값 해석 — "0.xxx" 소수

TCode 위치는 소수다: `L0500` = 0.500 = 50%, `L05` = 50%, `L0050` = 5%.
자릿수를 **왼쪽**으로 채우면 50% 가 5% 로 바뀐다 (`device_drivers.js` 에 같은 함정이
주석으로 남아 있다). 막대가 드라이버와 다르게 읽으면 **화면이 거짓말을 한다.**

→ `scripts/test_axis_bars.mjs` (26개) — 드라이버의 `encode()` 를 거친 값과 대조해
  정규화가 의미를 바꾸지 않는지 본다. 파서는 **베껴 쓰지 않고 `device_lab.ejs` 에서
  떼어내 실행한다** — 베끼면 원본이 바뀌어도 테스트가 통과해 버린다.

## 3. 검증

**자동 203개 통과** — 축 막대 26 · 릴레이 부하 50 · BLE 입력 26 · 연결 해제 13 ·
카메라 36 · ICE 25 · 미디어 게이트 20 · 재생 속도 7.
(앞선 기록에 190 으로 적었는데 `test_device_disconnect.mjs` 13개를 빼먹은 수였다 — 정정)

**실제 브라우저** — 가짜 BLE 스택으로 사인파를 흘려 확인:
L0·R1 두 축 자동 생성, 수신 87.2% / 송신 87.6%, **지연 평균 11ms · 최대 30ms (92건)**,
중간에 복사를 끄자 곡선에서 **송신만 끊기는 게 그대로** 보였다(타이밍 카드의 전송 최대도
1151ms 로 튀었다). 375px 폭에서도 레이아웃 정상, 콘솔 오류 0.
