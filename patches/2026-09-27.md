## 화면에 뜨는 것

연결 전(2초마다 갱신):

```
ICE 경로 탐색 중 · 상대응답 ✓ · 내 후보 [로컬망, 공인IP]
```

- **상대응답 ✗ 로 멈춤** → SDP 가 안 왔다 = **시그널링 구간** 문제 (NAT 이전)
- **상대응답 ✓ 인데 탐색만 계속** → 경로 문제 = **릴레이(TURN) 영역**
- **내 후보에 `공인IP` 가 끝내 없음** → STUN 자체가 막힘

연결되면 실제로 선택된 후보쌍: `연결됨 · 경로 로컬망 ↔ 로컬망`
실패하면: `ICE 실패 — 직결 경로를 못 찾았습니다 (릴레이 필요)` / `연결 실패 — <사유>`

콘솔 로그에도 `[ICE]` 접두사로 남는다.

## 알려진 공백 (아직 안 고침)

**ICE 서버 설정이 코드 어디에도 없다.** `iceServers`/`turn:` 문자열 0건 —
simple-peer 기본값(Google·Twilio **STUN만**)으로 돈다. **TURN 릴레이가 없으므로
직결이 안 되는 조합에서는 대안이 없다.** 위 진단에서 "릴레이 필요"가 확인되면
ICE 서버를 설정에서 주입하도록 바꾸고 TURN(Cloudflare Realtime TURN 또는 coturn)을 붙여야 한다.
이건 구조 변경이라 사용자 확인 후 진행한다.

## 결론 — 원인은 BJ PC의 VPN (2026-09-27 확정)

**BJ 쪽 PC에서 VPN을 끄자 즉시 연결됐다.** 코드 문제가 아니었다.

### 진단이 어떻게 좁혀갔는가 (같은 증상을 또 만나면 이 순서로 본다)

| 단계 | 화면에 뜬 것 | 읽은 것 |
|---|---|---|
| ① | `상대응답 ✓` | SDP 교환은 끝났다 → 시그널링·매칭 정상 |
| ② | `상대 후보 [없음] · 쌍 0` | 상대 ICE 후보가 하나도 안 들어왔다 → NAT 이전 문제 |
| ③ | 시청자 `송신 candidate 20` ↔ BJ `수신 candidate 20` | **서버 릴레이 정상** (20개 다 도착) |
| ④ | `후보투입 20/거부 0`, `host 16 srflx 4` | 투입도 정상, 주소도 실주소 → **mDNS 가설 폐기** |
| ⑤ | BJ `송신 [answer 1]` — 자기 후보 0개 · 후보 `[로컬망]` 하나뿐 · 공인IP 없음 | `setLocalDescription` 은 성공했는데(answer 를 보냈으므로) 후보를 안 흘린다 = **BJ 브라우저의 후보 수집이 억제됨** → VPN 의심 → 적중 |

### 왜 이게 함정인가

- VPN 이 켜진 쪽은 **자기 후보를 못 만든다.** 상대가 후보를 20개 보내줘도 짝지을 자기 후보가 없으면 쌍은 0이다.
- 이때 화면에는 아무 실패도 안 뜬다. "통화 중"만 뜨고 카메라 버튼·세션 컨트롤이 잠긴 채 30초쯤 뒤 조용히 종료된다.
  → **연결 실패를 사용자에게 보여주는 장치가 없던 것이 이번 사건의 절반이다.** (그래서 이 진단을 남겨둔다)
- `상대 후보 [없음]` 을 보고 "NAT·릴레이 문제" 로 뛰면 엉뚱한 곳(TURN)을 판다. 내 후보 송출 개수를 먼저 봐야 한다.

### 남은 판단거리 — TURN

VPN 을 켠 상태로도 통화가 돼야 한다면 **TURN 릴레이가 필요하다** (릴레이 후보는 실주소이고
VPN·NAT 과 무관하게 짝이 맞는다). 지금은 `iceServers` 설정이 코드에 없어 STUN 기본값만 쓴다.
외부 작업자 SSH(Tailscale)와 통화를 같은 기기에서 같이 쓰려면 이 결정이 필요하다. 사용자 확인 대기.

## 후속 — 문구 분리 (사용자 / 운영자)

진단을 급히 붙이면서 시청자 화면에 `sdp=stable gather=complete` 같은 개발자 문구가 그대로 보였다. 분리했다.

| 화면 | 보이는 것 |
|---|---|
| 통화 화면(사용자) | `연결 중…` 뿐. **붙으면 줄을 지운다.** 상세는 브라우저 콘솔에만 (`[ICE] …`) |
| ↳ 6초 넘게 안 붙고 **내 후보가 0개** | `연결 중… VPN·보안 프로그램이 켜져 있으면 연결되지 않습니다 — 끄고 다시 시도해주세요` |
| ↳ 실패 | `연결 실패 — VPN…` 또는 `연결 실패 — 네트워크 경로를 찾지 못했습니다` (ICE·릴레이 용어 없음) |
| BJ 콘솔(운영자) | 전체 표기 그대로 (`verbose: true`) |
| 통화 URL `?diag=1` | 전체 표기 그대로 |

**왜 VPN 문구를 사용자에게 보여주는가:** 2026-09-27 의 실제 원인이 그것이었고, 사용자가 스스로
풀 수 있는 유일한 조치다. 내가 내보낸 후보가 0개라는 건 **내 브라우저가 후보를 못 만드는**
상태이므로(VPN·보안 프로그램·정책), 상대 잘못이 아니라는 판단이 가능하다.
